# База данных системы автоматизации футбольного клуба


## 1. Назначение системы

Система предназначена для комплексного управления внутренними процессами футбольной организации, включая:
* **Спортивный сектор:** учет игроков, тренерского состава, фиксация игровых позиций и номеров на футболках.
* **Медицинский штаб:** ведение электронных медицинских карт, мониторинг травматизма, контроль этапов реабилитации и закрепление ответственных врачей за игроками.
* **Управление инфраструктурой и матчами:** формирование календаря игр (домашние/выездные), интеграция со стадионами, контроль вместимости и генерация посадочных мест.
* **Коммерческий сектор:** управление клубным магазином (каталог товаров, категории, цены, складской учет), обработка заказов покупателей, автоматизация продаж билетов на конкретные матчи с привязкой к схеме стадиона.

---

## 2. Архитектурные особенности и схема связей

База данных спроектирована по реляционной модели и находится в **третьей нормальной форме (3NF)**, что минимизирует избыточность данных и предотвращает аномалии обновления.

### Логические блоки данных:
1. **Инфраструктура (`stadiums`, `stadium_seats`)** — иерархическая связь «один ко многим» (Один стадион содержит множество мест).
2. **Спортивный блок (`positions`, `staff`, `players`)** — справочник должностей/игровых позиций связывает сотрудников и футболистов.
3. **Медицина (`medical_records`)** — промежуточная таблица, связывающая травмированного игрока с лечащим врачом из таблицы персонала.
4. **Матчи и билеты (`matches`, `tickets`)** — каскадная генерация билетов на основе доступных мест стадиона для конкретного игрового события.
5. **CRM и Продажи (`customers`, `products`, `orders`, `order_items`)** — классическая e-commerce структура с поддержкой истории цен на момент покупки (`price_at_purchase`).

## 3. Подробное описание таблиц и полей

### 3.1. Таблица `stadiums` (Стадионы)
Хранит информацию о спортивных аренах.

| Поле | Тип данных | Ограничения | Описание |
| :--- | :--- | :--- | :--- |
| `stadium_id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный идентификатор стадиона |
| `name` | VARCHAR(100) | NOT NULL | Название арены (например, 'Вектор Арена') |
| `city` | VARCHAR(50) | NOT NULL | Город нахождения |
| `capacity` | INT | NOT NULL | Общая общая вместимость |

### 3.2. Таблица `stadium_seats` (Места на стадионе)
Детализация трибун стадиона.

| Поле | Тип данных | Ограничения | Описание |
| :--- | :--- | :--- | :--- |
| `seat_id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный идентификатор места |
| `stadium_id` | INT | FOREIGN KEY | Ссылка на `stadiums.stadium_id` (ON DELETE CASCADE) |
| `sector` | VARCHAR(10) | NOT NULL | Буквенный или цифровой код сектора |
| `seat_row` | INT | NOT NULL | Номер ряда (наименование изменено во избежание конфликтов с ключевыми словами) |
| `seat_number` | INT | NOT NULL | Номер кресла |

### 3.3. Таблица `positions` (Должности и игровые позиции)
Единый справочник для спортивного и административного персонала.

| Поле | Тип данных | Ограничения | Описание |
| :--- | :--- | :--- | :--- |
| `position_id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный идентификатор позиции |
| `title` | VARCHAR(50) | NOT NULL | Название ('Главный тренер', 'Врач', 'Нападающий') |

### 3.4. Таблица `staff` (Администрация и персонал)
Сотрудники клуба, исключая действующих футболистов основного состава.

| Поле | Тип данных | Ограничения | Описание |
| :--- | :--- | :--- | :--- |
| `staff_id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный идентификатор сотрудника |
| `first_name` | VARCHAR(50) | NOT NULL | Имя |
| `last_name` | VARCHAR(50) | NOT NULL | Фамилия |
| `position_id` | INT | FOREIGN KEY | Ссылка на `positions.position_id` |
| `salary` | DECIMAL(10,2) | | Ежемесячный оклад |
| `contract_end`| DATE | | Дата окончания трудового договора |

### 3.5. Таблица `players` (Футболисты)
Профессиональные метрики и текущий статус игроков.

| Поле | Тип данных | Ограничения | Описание |
| :--- | :--- | :--- | :--- |
| `player_id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный идентификатор игрока |
| `first_name` | VARCHAR(50) | NOT NULL | Имя |
| `last_name` | VARCHAR(50) | NOT NULL | Фамилия |
| `position_id` | INT | FOREIGN KEY | Ссылка на амплуа в `positions.position_id` |
| `jersey_number`| INT | | Игровой номер на футболке |
| `birth_date` | DATE | | Дата рождения |
| `status` | VARCHAR(20) | DEFAULT 'Здоров' | Состояние: 'Здоров', 'Травмирован', 'Дисквалифицирован' |

### 3.6. Таблица `medical_records` (Медицинская карта / Лазарет)
Логирование травм и процесса реабилитации.

| Поле | Тип данных | Ограничения | Описание |
| :--- | :--- | :--- | :--- |
| `record_id` | INT | PRIMARY KEY, AUTO_INCREMENT | Уникальный идентификатор записи |
| `player_id` | INT | FOREIGN KEY | Ссылка на `players.player_id` (ON DELETE CASCADE) |
| `doctor_id` | INT | FOREIGN KEY | Ссылка на `staff.staff_id` (лечащий врач) |
| `injury_title` | VARCHAR(100)| | Диагноз / характер повреждения |
| `recovery_start`| DATE | | Дата получения травмы |
| `recovery_end` | DATE | | Планируемая или фактическая дата восстановления |
| `status` | VARCHAR(20) | | Статус лечения: 'Лечение', 'Восстановление', 'Завершено' |

### 3.7. Таблица `matches` (Календарь матчей)
Расписание спортивных встреч.

| Поле | Тип данных | Ограничения | Описание |

| `status` | VARCHAR(20) | DEFAULT 'Доступен' | Состояние: 'Доступен', 'Забронирован', 'Продан' |

## 4. Схема жизненного цикла объектов (Статусная модель)

Управление сущностями завязано на строгой валидации текстовых статусов. Ниже описаны переходы состояний:

* **Матчи (`matches.status`):** `Запланирован` ➔ `Идет` ➔ `Завершен` (или `Отменен`).
* **Игроки (`players.status`):** `Здоров` ➔ `Травмирован` (блокирует появление в стартовых протоколах матчей) или `Дисквалифицирован`.
* **Заказы мерча (`orders.status`):** `Новый` ➔ `Оплачен` ➔ `Выполнен` (или `Отменен` с возвратом остатков на склад).
* **Билеты (`tickets.status`):** `Доступен` ➔ `Забронирован` ➔ `Продан`.

## 5. Описание аналитических представлений (Views)

Для оптимизации бизнес-логики и исключения тяжелых регулярных запросов с операторами `JOIN` спроектированы системные представления:

1. **`view_upcoming_matches`**:
   Выводит сводную панель для кассиров и витрины сайта. Показывает идентификатор матча, имя соперника, дату проведения, текстовое название стадиона, общее количество выпущенных билетов и динамически вычисляемый остаток билетов со статусом `'Доступен'`.
2. **`view_injured_players`**:
   Панель мониторинга для главного тренера и медицинского департамента. Соединяет данные футболистов, их диагнозы из карт и ФИО лечащих врачей. Фильтрует только тех, кто находится в процессе лечения или реабилитации.
